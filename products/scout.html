Palm-vein authentication

PalmFaith Scout

A dedicated biometric authentication device designed to verify the person, not merely the password, phone or access token they carry.

Scout uses the unique vein pattern inside the palm as an authentication factor. The user presents a hand to the device and is verified without typing a password, scanning a card or depending on a mobile phone.

The central question

Does Scout solve a problem that current authentication methods do not solve?

Many authentication systems verify something the user knows or possesses. Scout is designed to verify a biometric characteristic that is physically present inside the user’s hand.

Passwords can be forgotten, shared, stolen or reused. Phones and security keys can be lost, transferred or unavailable. Palm-vein authentication introduces a different form of verification: the person must be physically present at the moment access is requested.

Why reconsider authentication?

Digital access still depends heavily on credentials that can be copied, transferred or compromised

Scout is intended for situations where an organisation wants stronger assurance that the authorised person is genuinely present.

01

No password to remember

The user does not need to recall, enter or regularly replace a password in order to authenticate.

02

No phone dependency

Authentication does not depend on a personal mobile phone, text message or authentication application.

03

No transferable credential

A palm-vein pattern cannot be handed to another person in the way a password, card, phone or security key can.

04

Physical presence

The authentication process is designed to require the enrolled user to be present at the device.

05

Contactless use

The user presents a hand above the reader without needing to touch a shared scanner surface.

06

Simple user action

Authentication is reduced to a direct and familiar action: presenting the palm to the device.

How Scout works

From palm presentation to digital access

Scout is designed to make the authentication process direct for the user while supporting a stronger identity decision behind the scenes.

1

Present the palm

The user holds a registered hand above the Scout reader.

2

Read the vein pattern

The device captures the internal palm-vein pattern used for biometric verification.

3

Verify the user

The presented biometric information is checked against the enrolled authentication record.

4

Authorise access

When verification succeeds, the connected system can continue its login or access process.

Possible environments

Where might Scout be relevant?

Scout may be considered where an organisation needs more confidence that access is being requested by the authorised person rather than by someone holding that person’s credentials.

Shared workstations

Environments where multiple authorised users access the same computer or terminal.

Sensitive systems

Systems containing information or functions that require stronger identity assurance.

Controlled operations

Operational environments where credentials must not be passed between colleagues.

Users without smartphones

Situations where mobile-phone-based authentication is inconvenient, undesirable or unavailable.

Customer-facing access

Services that need a simple authentication action without asking the user to remember another password.

Higher-assurance workflows

Selected actions or transactions where ordinary login credentials may not be sufficient.
